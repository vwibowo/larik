Execution

Tool calls or scripts.
Chosen per model.

A model can write a short script that calls your tools. Loops, chained lookups and filtering happen in the script, and only what it prints comes back. Reading forty files to count something costs the context one summary, not forty results.

Execution guide
{{code "js" `// run_code: tests per package, top five const hits = tools.grep({ pattern: "^func Test", glob: "*_test.go" }) const perPkg = {} for (const line of hits.split("\n")) { const file = line.split(":")[0] if (!file.endsWith("_test.go")) continue const pkg = file.slice(0, file.lastIndexOf("/")) perPkg[pkg] = (perPkg[pkg] || 0) + 1 } Object.entries(perPkg).sort((a, b) => b[1] - a[1]).slice(0, 5)`}}

Hundreds of matches in, five rows out.

The script sees the full results; the conversation sees the answer. Fewer turns, a smaller context, and nothing copied by hand.

{{code "json" `{ "execution": "tools", "model_execution": { "codex/gpt-6-luna": "code", "claude-opus-5": "hybrid" } }`}}

Three settings, one per model.

tools: one call per step. hybrid: the model picks scripts or calls each step. code: scripts only. Pick with /execution; switching models switches the setting.

  • Same rules for every call a script makes: permissions, hooks, auto mode, /undo
  • Sandboxed: no writes, no network, no keys, 256 MB cap
  • larik bench --execution measures it on your model

Subagents in git worktrees

Parallel subagents with fresh contexts. Isolated ones work on their own branch for the main agent to review and merge.

Branch, rewind, undo

/fork a conversation, /rewind to before any prompt, /undo the last turn's file changes, resume any of them later.

MCP, with approval

stdio, HTTP or SSE servers with OAuth sign-in. Servers from shared project files wait for your approval.

Tools on demand

With dozens of MCP tools connected, the model searches for the one it needs instead of carrying every definition in every request.

Language servers

Diagnostics after every edit, so the model sees the type error it just introduced. Jump to definitions, apply code actions.

Web fetch and search

Pages as clean Markdown. Domain rules, blocked metadata addresses, cross-host redirects reported rather than followed.

Browser control

Drives a real Chrome window: click, type, upload, read frames and network requests. Every request is checked, sign-ins persist.

Permissions you control

Five modes, from plan to yolo, on shift+tab. Allow and deny rules with globs; deny always wins.

Auto mode

A model approves routine steps against your recent prompts. Pushes, deletes, secrets and sudo still ask, with the reason.

Plan, then approve

In plan mode the model reads, then puts its plan to you. Longer work runs from a checklist in the sidebar.

Reviews and a GitHub Action

/review and /security-review report findings with file, line and fix. The Action posts them on every pull request.

Memory

Your preferences, corrections and project decisions, kept as short notes outside the repo and recalled in later sessions.

A project-aware prompt

@ attaches files and images, ! runs a shell command, ctrl+r searches history.

Debug traces

--debug records every request as sent. larik trace opens a timeline that diffs each prompt against the last.

Make it yours

Your own status line, rebindable keys, vim mode for the prompt, light or dark themes.

Designed around the loop

One static binary.
Small choices that keep it fast.

no Node
no Python 1 go build
starts in ms

Cache-stable prompts

The system prompt and tool set stay fixed within a context and the transcript is append-only, so every request after the first reads from the prompt cache.

Reasoning kept per model

Switch from Claude to GPT to a local model mid-session. Each model gets its own thinking replayed.

Clean compaction

When context fills, the history becomes one summary that names the transcript file, so the model can grep what it left out.

No runtime to install

Build it with go build, copy it anywhere, start it in milliseconds.
